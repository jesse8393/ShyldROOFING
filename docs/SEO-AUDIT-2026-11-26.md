## Scope and method

* **Crawl.** `scripts/audit/seo_crawl.py` fetched all 60 sitemap URLs, followed every internal link, and fetched all
  246 referenced assets plus the two scripts loaded by dynamic import. `scripts/audit/seo_analyze.py` produced
  `docs/seo-audit-2026-11-26/onpage-crawl.md` (per page table).
* **Lighthouse 12.8.2** with the bundled Chromium, default mobile emulation and simulated throttling. The sandbox
  browser cannot complete TLS to outside hosts, so Lighthouse ran against a byte for byte local mirror of the live
  files (`scripts/audit/mirror.py`, served with `http-server -e html`, host name mapped to 127.0.0.1). Two audits that
  cannot pass on a plain HTTP mirror were skipped and verified with curl on the live server instead: `is-on-https`
  (live: HTTPS with HSTS) and `redirects-http` (live: `http://` returns 301 to `https://`). The Google tag loader was
  pointed at an empty local stub so the mirror did not call out. Zero weight diagnostics about text compression,
  HTTP/2 and back/forward cache describe the mirror server, not the live server; live responses use Brotli, HTTP/2 with
  HTTP/3 advertised, and `Cache-Control: no-cache` on HTML.
* **PageSpeed Insights API** was attempted for real Chrome field data (CrUX) and returned HTTP 429 (keyless daily quota
  exhausted). No field data is included. Run https://pagespeed.web.dev/ manually for CrUX.
* **Indexing.** Google search blocked automated queries (JavaScript challenge, then the session's permission layer
  denied a second attempt). Search Console API access is not configured for this session. Bing was queried once with
  `site:` and `url:` operators. The jesse@parkerconstructioncompany.com inbox was searched for Search Console mail about
  this domain (none in 120 days; the domain's Search Console property is evidently on another Google account).
* **Source comparison.** Every branch of this repository was fetched and the newest one (`claude/jakarta-preview`,
  ab3af27, pushed 2026-10-07) was built and compared file by file with the live server.

## Indexing status

**What is confirmed:** nothing on the server prevents indexing. All 60 pages return 200, are self canonical, have no
noindex, are in the sitemap, and are linked internally. The Search Console verification file is served.

**What could not be confirmed from this session:**

* Whether Google has indexed the 60 pages. Google's results page could not be read by an automated client here and
  Search Console is not connected. The owner can confirm it in minutes:
  1. Open Search Console for the `shyldroofing.com` property (the verification file is in place, so the property exists
     under whichever Google account verified it; no Search Console mail for this domain arrives at the Parker inbox).
  2. Indexing, then Pages: the "Indexed" count should be 60. Any page under "Discovered, currently not crawled",
     "Crawled, currently not indexed" or "Duplicate" needs attention.
  3. Indexing, then Sitemaps: `https://shyldroofing.com/sitemap.xml` should show "Success" with 60 discovered URLs.
     If it is not listed, submit it.
  4. URL Inspection on the home page, the six service pages and three city pages. If any shows "URL is not on Google",
     use "Request indexing".
* The 30 outer city pages (Antioch through Kingston Springs) went live on 2026-10-09 with only 2 to 8 internal links
  each, compared with 65 to 70 for the 14 core city pages. They are discoverable through the sitemap and the service
  areas hub, but low link counts and shared template text make them the most likely pages to sit in "Crawled, currently
  not indexed".

**Bing.** On 2026-11-26 Bing answered `site:shyldroofing.com` with "There are no results for site:shyldroofing.com"
and `url:shyldroofing.com` with unrelated results. Treat this as a strong signal, not proof, that Bing has not indexed
the site. Bing's index feeds Microsoft Copilot, ChatGPT browsing and DuckDuckGo. Fix: create a Bing Webmaster Tools
account, use "Import from Google Search Console", submit the sitemap, and use its URL submission (IndexNow) for the 60
URLs.

## Structured data

Every page carries one JSON-LD graph that parses without errors.

| Type | Where | Notes |
| --- | --- | --- |
| `RoofingContractor` with `@id` `#business` | All pages | Correct LocalBusiness subtype. Has `name`, `legalName`, `url`, `telephone`, `email`, `image`, `logo`, `priceRange`, `address` (city, region, postal code, country, no street, correct for a service area business), `geo`, `openingHoursSpecification` (matches the visible hours), `areaServed` with all 44 towns. |
| `WebSite` | Home | Publisher linked to the business. |
| `BreadcrumbList` | All pages except home | Matches the visible breadcrumbs. |
| `Service` | 6 service pages, 44 city pages | `provider` links to the business. City pages use `areaServed` of type `City` (36 pages) or `Place` (8 pages for neighborhoods and unincorporated places such as Antioch and Bellevue), which is the right distinction. |
| `Article` | 2 guides | `headline`, `description`, `datePublished`, `dateModified`, `mainEntityOfPage`, `author` and `publisher` as the business. |

Improvements, none of them errors:

* No `sameAs`. Add the Google Business Profile URL and any real social profiles to the business node once they exist.
  This is the single most useful structured data addition for a local business entity.
* `Article.author` is the organisation. A `Person` node for the owner (name, `jobTitle`, `worksFor`, `sameAs`) on the
  About page and as the article author strengthens experience and expertise signals.
* `Article.image` is the generic Open Graph image on both guides. Use a page specific image.
* No `aggregateRating`. Correct: do not add one until real reviews exist, and then only with the real count.
* The FAQ sections have no `FAQPage` markup. Google restricted FAQ rich results to government and health sites in
  2023, so adding it brings no Google benefit; it can help AI assistants quote the answers. Optional.
* `geo` has four decimal places (about 10 metres). Fine for a service area business that does not publish a street
  address.

## Reproducing this audit

```
# crawl and on page analysis (needs only python3 and curl)
curl -sS https://shyldroofing.com/sitemap.xml | grep -o '<loc>[^<]*</loc>' | sed 's/<\/\?loc>//g' > /tmp/urls.txt
python3 -I scripts/audit/seo_crawl.py /tmp/audit /tmp/urls.txt
python3 -I scripts/audit/seo_analyze.py /tmp/audit/crawl.json > /tmp/audit/onpage-summary.md

# local mirror and Lighthouse (needs node, lighthouse, chrome-launcher, http-server)
python3 -I scripts/audit/mirror.py /tmp            # writes /tmp/mirror from /tmp/audit/crawl.json
http-server /tmp/mirror -p 80 -a 127.0.0.1 -e html -s &
node scripts/audit/lighthouse-mirror.mjs /tmp     # reads /tmp/sitemap-urls.txt, writes /tmp/lh/
```

Lighthouse against the live site directly (`npx lighthouse https://shyldroofing.com/`) is the better choice on any
machine that can reach the internet normally; the mirror exists only because this sandbox cannot.
